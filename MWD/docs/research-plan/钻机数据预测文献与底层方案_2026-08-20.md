# 钻机/随钻数据预测：文献与底层方案

更新时间：2026-08-20
项目目录：本仓库的 `MWD/` 模块

> 本版为第二轮文献复核后的方案。相较初版，已将“自监督/物理约束/不确定性”从单独的创新宣称，调整为有文献依据的组件；候选创新集中在岩体状态与钻机工况的分解、过渡带弱监督、跨隧道验证和统一可信度评估。任何“首次提出”的表述仍需在正式投稿前做系统综述检索确认。

## 1. 先明确研究对象

“钻机数据预测”至少包含四个不同问题，不能用一个指标混评：

1. **钻进过程预测**：ROP/钻速、扭矩、压力、能耗、下一时刻传感器值。
2. **地质状态预测**：岩性、岩体强度、围岩质量、结构面/过渡带。
3. **风险和设备状态预测**：卡钻、漏失、kick、异常工况、部件故障和剩余寿命。
4. **施工决策预测**：支护等级、钻进参数推荐、注浆量/压力/效果。

结合当前目录中的数据，最适合的起点是 **MWD/钻机参数 -> 岩性与岩体状态**，再把同一个编码器扩展到 ROP、风险和注浆决策。现有数据 `mwd_rocktype_blastholes_model_ready_full.csv` 有 55 个 CSV 字段，其中 54 个有命名（另有 1 个空表头）：`Tunnel`、深度区间 `PegStart/PegEnd`、5 组钻进信号的统计特征、`Rock`、`transition_zone` 和 `round_length`。这使得“岩性分类 + 过渡带识别 + 不确定性”可以立即开始。

需要特别区分：当前 Zenodo 文件是**按钻进区间聚合后的样本级数据**，包含统计特征和深度区间，并不是可以直接按时间步做 masked-span 预训练的连续原始传感器流。项目中的 `raw.csv` 也仍是样本级字段，只是较少清洗/处理的版本。若要训练真正的连续时序底座，需要补充每个孔的深度采样序列、采样间隔和设备/工况元数据。

## 3. 现有工作的共同空白

下面不是断言所有论文都存在同样问题，而是根据第二轮阅读中明确出现的实验设置和当前数据的组合，得到的可验证研究空白：

1. **统计聚合是主流，连续序列证据不足**：Hansen、Hou、Chen 等工作都说明聚合特征很有效，但这也留下了原始深度序列、局部突变和跨尺度信息是否真正有用的问题。
2. **随机切分仍很常见**：TBM 文献中明确使用随机 90/10 或类似切分；少数工作使用 unseen well。需要把按隧道/井留出作为主实验，而不是补充实验。
3. **过渡带是已证实的难点而非假设难点**：Hansen 的十类任务中，过渡区表现明显下降；因此 `transition_zone` 应成为目标和评价切片。
4. **深度模型并不稳定领先**：UCS 和漏失研究中，RT/SVR/RF 等模型可能优于 CNN/LSTM；新底座必须以强表格模型为对照，证明数据协议和迁移价值。
5. **数据预处理本身会改变结论**：异步采样、缺失填补、归一化、窗口和标签对齐都被钻井时序文献证明会影响结果；需要版本化并做敏感性实验。
6. **物理融合已有多种范式**：ROP 残差建模和 PINN 都已有先例；创新应放在现场 MWD 的状态分解、弱标签和跨域验证，而不是笼统地说“加入物理约束”。
7. **异常检测和地质预测尚未形成同一底层状态空间**：LSTM-AE 已能在正常数据上发现卡钻早期异常，但其表征能否迁移到岩性/强度任务，需要专门验证，不能直接假定。

## 4. 经文献复核后的自有底层方案：DrillBase-RM

暂定名称：**DrillBase-RM（Rock-Machine）：面向岩体-钻机交互状态的跨工况预测底座**。

核心思想：把观测到的钻进响应拆成三个潜变量：相对稳定的**岩体状态**、快速变化的**钻机/工具工况**、以及两者产生的**交互响应**。任务头再从共享状态中预测岩性、过渡带、强度/Q-class、ROP 和异常风险。这个方案的候选贡献不是单一网络模块，而是统一的状态分解、弱标签训练、跨隧道评估和可信度输出。

```text
样本级统计特征 / 连续 MWD 流 / 工况元数据
        |
数据质量掩码 + 深度位置编码 + 隧道/钻机/钻具域编码
        |
岩体状态编码器 + 机器状态编码器 + 交互门控
        |
重构钻进响应，并约束岩体表征对域变化更稳定
        |
岩性 | UCS/Q-class | 过渡带 | ROP残差 | 异常分数 | 校准/拒答
```

### 4.1 候选创新点：必须通过消融和跨域实验成立

**候选点 1：岩体-机器状态分解，而不是单纯增加网络深度。**

模型分别编码慢变化的深度/岩体状态和快变化的钻机状态，再通过交互模块生成传感器响应。用域分类器或对抗损失约束岩体表征不依赖具体隧道/钻机，同时保留机器表征用于解释工况。只有当 leave-one-tunnel-out 的性能优于无分解模型时，才能把它写成方法贡献。

**候选点 2：过渡带的弱监督和区间预测。**

`transition_zone` 不再只作为普通二分类标签，而用于构造邻域标签分布：边界样本允许多个岩性概率共存，并单独输出过渡带概率。评价同时报告普通区、过渡区、类别边界距离和拒答率。这一设计直接回应 Hansen 论文报告的过渡区性能下降。

**候选点 3：统一表征的可迁移任务头。**

用自监督重构、下一窗口预测或 TS2Vec/TimesURL 对比学习作为表征学习基线；但只有在取得连续 MWD 流后才执行。当前统计特征数据先训练表格版状态编码器，待连续序列到位后再比较两种输入形式。岩性、过渡带、UCS/Q-class、ROP 和异常任务共享编码器但独立任务头，报告低标签微调和跨域迁移收益。

### 4.2 物理/工程约束的使用方式

物理融合不是总模型的默认损失，而是按任务分层使用：

- **ROP 头**：复现 Jiao 等人的 residual modeling，先得到理论/经验基线，再学习残差；必须确认 WOB、RPM、扭矩、流量等单位和适用钻具。
- **UCS 头**：参考 Li/Wei/Zhang 等机械模型或 PINN，但只在有可校准的现场参数时使用；实验室 PINN 结果不能直接外推到隧道现场。
- **岩性头**：不强行施加单调性物理公式；先做标签质量、过渡带和跨隧道校准。
- **质量控制**：压力、流量、进尺等累计量的单调性、量纲和时间顺序用于数据质量标记，而不是静默修正。

## 5. 推荐的最小可行研究问题

建议先不要把题目写成宽泛的“钻机数据预测”。基于当前样本级数据，第一篇论文可以定义为：

> **面向跨隧道泛化的多任务随钻岩性预测：岩体-钻机状态分解与地质过渡带弱监督。**

输入：第一阶段使用当前 CSV 的 48 个 MWD 统计特征；连续原始 MWD 流和采样元数据到位后，再开展序列底座实验。
主任务：`Rock` 多分类。
辅助任务：`transition_zone` 二分类、`round_length` 回归或区间预测。
后续任务：Q-class/UCS；若标签不足，先做迁移学习和小样本微调。
主实验：随机切分只作复现对照；主结果使用按 `Tunnel` 分组的 leave-one-tunnel-out，并补充按深度顺序的 forward split。
核心指标：Macro-F1、Balanced Accuracy、过渡带 F1、ECE/覆盖率、跨隧道性能下降幅度。

## 6. 实验矩阵

### 基线

- LightGBM/XGBoost：当前表格特征的强基线。
- MLP：验证是否只是静态特征可分。
- TCN/1D-CNN：局部深度变化基线。
- Transformer/Temporal Fusion Transformer：长依赖基线。
- DrillBase-RM：状态分解 + 多任务 + 域泛化 + 不确定性。

### 必须做的消融

1. 当前统计特征 vs 连续 MWD 序列（连续数据取得后）。
2. LightGBM/ExtraTrees/SVR vs 神经网络。
3. 单任务 vs 多任务。
4. 硬标签 vs 过渡带软标签/边界损失。
5. 无状态分解 vs 岩体/机器/交互状态分解。
6. 无域适配 vs 域解耦。
7. 无校准 vs 校准/拒答机制。
8. ROP 纯 ML vs 物理基线残差模型。

### 数据切分原则

- 不允许把同一 `Tunnel` 或相邻深度窗口无意拆到训练和测试两侧。
- 至少固定一个 leave-one-tunnel-out 测试协议。
- 预处理器、标准化参数、类别权重只在训练折拟合。
- 所有实验保存随机种子、数据版本、特征清单、模型配置和 commit id。

## 7. 12 周落地顺序

| 周期 | 产出 |
|---|---|
| 第 1-2 周 | 数据审计：字段单位、缺失、异常、类别分布、隧道分布、相邻窗口重复风险 |
| 第 3 周 | LightGBM/MLP 基线，建立 tunnel-level split 和可复现实验配置 |
| 第 4 周 | TCN/Transformer 只作为可选基线；先确认当前数据并非连续时序 |
| 第 5 周 | 岩性 + `transition_zone` 多任务表格模型，加入软标签/边界损失 |
| 第 6 周 | 固化 leave-one-tunnel-out、forward split 和数据质量敏感性实验 |
| 第 7-8 周 | 实现岩体/机器/交互状态分解，比较跨隧道性能和解释稳定性 |
| 第 9 周 | 温度校准/深度集成/conformal prediction，报告拒答和覆盖率 |
| 第 10 周 | 获取连续 MWD 流后做 masked/contrastive 预训练；否则暂不宣称时序基础模型 |
| 第 11 周 | 加入 Q-class/UCS 或第二数据源，做迁移和小样本实验 |
| 第 12 周 | 消融、统计显著性、失败案例、论文图表和开源复现实验包 |

## 8. 目前的结论

最值得做的不是“再换一个更大的 Transformer”，也不是把已有的 PINN、stacking 或 LSTM-AE 重新包装。更稳妥的研究贡献是：建立一个区分岩体状态和机器工况的钻进响应底座，针对过渡带进行弱监督学习，在严格的跨隧道协议下同时输出预测和可信度。当前数据足以做第一篇表格型方法论文；连续 MWD 流、Q/UCS 标签或 ROP 数据到位后，再扩展为真正的时序底座和多任务迁移系统。

## 9. 第二轮文献复核后的实施判断

### 9.1 当前阶段可以马上做的内容

- 复现 Hansen 的 LightGBM/ExtraTrees/MLP 级别基线，并严格保留其 48 特征与标签定义。
- 用 `Tunnel` 做 leave-one-tunnel-out；将论文中的随机切分结果只作为复现对照。
- 针对 `transition_zone=True` 单独报告 Macro-F1、混淆矩阵、置信度和拒答率。
- 构造岩体状态、机器工况、交互响应三组特征的可解释版本，先用树模型验证状态分解是否有价值。

### 9.2 当前阶段不能直接承诺的内容

- 不能把当前 CSV 称为连续时序数据或时序基础模型训练集。
- 没有现场 Q-class/UCS/ROP 标签时，不能报告这些任务的实际预测效果，只能做方法接口或迁移实验。
- 没有单位、钻具几何和工况边界时，不能把特定能量或破碎力学公式直接写进损失函数。
- 没有跨隧道外部测试时，不能把随机切分上的高准确率称为工程泛化。

### 9.3 第一篇论文的建议题目

中文：**考虑岩体-钻机状态分解与地质过渡带弱监督的跨隧道随钻岩性预测**。
英文：**Cross-tunnel lithology prediction from measurement-while-drilling data with rock-machine state disentanglement and transition-aware weak supervision**。

这一定义比“钻机数据基础模型”更适合当前数据规模，也更容易形成明确的对照实验。待连续 MWD 数据获得后，再把自监督预训练作为第二篇或扩展章节，而不是在第一篇中预先承诺。

数据集使用前要再次核对 Zenodo 页面许可：页面显示 CC BY 4.0，但记录描述同时出现“仅限科研/不可商业使用”的文字。论文发表、模型开源或商业化前应向数据作者书面确认。
