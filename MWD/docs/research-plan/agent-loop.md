# 受约束实验 Agent 闭环

## 核心职责

当前实现推进论文路线中的“读取验证结果、诊断切片差异、选择下一动作、执行实验、比较并停止”。语言模型宿主负责提出动作，`run_mwd_agent.py` 负责执行工具与约束检查。模型不直接预测岩性，也不控制施工设备。

这是宿主驱动的闭环：运行本项目的语言模型读取观察 JSON，写入动作 JSON，再调用执行器。本地工具不内置远端 LLM API，也没有以固定规则模拟 LLM 决策。单独运行 init 只会建立基线，后续动作需要宿主继续提供。

## 可执行接口

```bash
.venv/bin/python run_mwd_agent.py init --session reports/agent_loop/session-001 --budget 4
.venv/bin/python run_mwd_agent.py observe --session reports/agent_loop/session-001
.venv/bin/python run_mwd_agent.py act --session reports/agent_loop/session-001 --action proposal.json
```

初始化执行完整 48 特征 LightGBM 基线。观察响应包含当前 revision、当前最优配置、候选结果、剩余预算、允许候选和 observation_sha256。宿主只能根据该观察提供动作，不使用历史测试结果或直接读取测试数据。

运行候选的动作结构：

```json
{
  "action": "run_candidate",
  "candidate": "all_48__extratrees",
  "reason": "说明当前验证结果中的具体问题",
  "hypothesis": "说明候选可能改善问题的假设",
  "physical_risk": "说明删减特征或改变模型的物理信息风险",
  "observation_sha256": "来自最新观察响应的哈希"
}
```

停止动作只包含 action（stop）、reason 和 observation_sha256。哈希必须与当前观察一致；未知字段、任意路径或命令、重复候选、超预算以及会话停止后的动作会被拒绝。理由字段记录宿主推理，但执行器仅验证格式，不能证明推理正确。

## 预算与晋级规则

候选限定为 all_48 + LightGBM、all_48 + ExtraTrees、central_statistics + LightGBM、variability_statistics + LightGBM。完整特征基线计入最多四个候选的预算，每候选固定五种子 11、19、42、73、101，最多 20 次训练尝试。训练失败也消耗该候选预算并记录已尝试种子，不自动无限重试。

采用既有公开训练集内部 80/20 随机分层验证及既有欠采样/SMOTE。选择分数仍为 0.2 Balanced Accuracy + 0.5 Macro-F1 + 0.3 过渡区 Macro-F1。晋级必须同时满足：综合分数均值超过当前配置至少 0.001（严格大于阈值）、整体 Macro-F1 均值不低于初始基线、过渡区 Macro-F1 均值不低于初始基线。未通过者保留结果但不替换当前配置。预算耗尽自动停止。

本阶段没有开放质量阈值动作：既有实验尚不支持 IQR 代理默认投入使用。也没有开放任意特征列表、任意参数、代码执行或数据路径。

## 复现与边界

会话输出采用不可覆盖的递增 state-NNNN.json 快照；动作理由、候选配置、逐种子指标、晋级或拒绝原因均可追溯。CLI 固定读取公开训练文件，记录并在下一轮校验源文件、执行代码、Python 与依赖版本；会话锁避免并发操作。若进程被外部终止，可能留下锁且未落盘的当前训练不计入已记录预算，需人工检查后重新建立会话；不支持无损崩溃续跑。

工具白名单不是操作系统沙箱，不能限制宿主本身的全部文件权限。训练文件哈希用于复现而非认证。当前使用既有随机行划分，共享空间相关数据且历史研究已经反复使用这些验证样本，因此只能证明闭环能够执行，不能据此宣称独立泛化或 Agent 优于人工、随机搜索。后续方法比较须统一候选与预算，并补齐固定流程、普通搜索及有无约束的对照。

当前初始化在基线运行后记录代码指纹，因此初始化期间不得修改执行文件。本次实验开始前冻结了执行代码，全部轮次保持不变。运行中的版本管理仍有改进空间，这一限制不能解释成支持并发热更新。

## 首轮实际闭环：2026-09-08

当前语言模型宿主逐次读取观察结果，写入 proposal-001 至 proposal-003 并执行，并非预先提交全部动作。输出位于 `reports/agent_loop/2026-09-08/`。四份递增状态快照记录各轮结果；三个提案中的观察哈希已逐一核对与前一状态一致。

| 配置 | 整体 Macro-F1 | 过渡区 Macro-F1 | Selection Score | 执行器决定 |
|---|---:|---:|---:|---|
| 完整 48 特征 + LightGBM | 0.8224 | 0.5632 | 0.7491 | 建立基线 |
| 完整 48 特征 + ExtraTrees | 0.8155 | 0.5697 | 0.7477 | 拒绝晋级 |
| 均值/中位数 + LightGBM | 0.7987 | 0.5814 | 0.7385 | 拒绝晋级 |
| 离散度/高阶统计 + LightGBM | 0.7483 | 0.5274 | 0.6868 | 拒绝晋级并停止 |

表中均为固定五种子的验证均值；标准差和逐种子结果见状态 JSON。数值不与之前使用 60/20/20 数据划分的校准实验直接比较。

动作链：基线的过渡区差距触发保留全部信息、更换模型族的假设；ExtraTrees 局部提高过渡区但总体退化，随后检查中心统计能否降低估计噪声；中心统计的整体表现下降且种子波动更大，最后检验互补的波动统计。三个候选均未符合全部条件，最终保留原基线，预算耗尽停止。

实际完成 20 次模型训练，零训练失败；模型训练及评估合计约 37.36 秒（不含宿主推理、提案编写及工具调度时间）。本轮没有提交非法动作；非法/过期动作处理由测试验证，不能据此推断真实 LLM 非法动作率为零。宿主模型的 token 数和远端 API 调用数未计量，不补造成本数据。

本轮验证了工具闭环和防退化规则有效执行，没有证明 Agent 带来性能提升。候选目录只有四项且全部被评估，所以也不能证明本轮动作顺序比穷举更高效。下一项核心研究工作是同预算的固定流程/普通搜索/宿主 Agent 对照，并以相同日志结构记录每步最佳分数、过渡区表现和计算消耗；不再把增加复核工具作为主要推进方向。

同预算的事后顺序回放现已完成，详见 [search-comparison.md](search-comparison.md)：所有方法在所有预算点持平，当前候选目录没有改善机会。这不是多次独立 LLM 对照试验；下一轮须先扩展有研究依据的候选动作，并采用小于目录规模的预算。
