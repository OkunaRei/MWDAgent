# 同预算搜索顺序对照

## 问题与协议

在相同候选结果、相同评估成本和晋级规则下，当前宿主 Agent 的动作顺序能否更早找到可用的更好配置？

```bash
.venv/bin/python compare_agent_search.py \
  --session reports/agent_loop/2026-09-08 \
  --output-dir reports/search_comparison/new-run
```

这是一轮事后搜索顺序回放，不是重新运行多次 LLM 决策。输入为上一轮完整四候选实验的递增状态文件。加载器检查动作引用前一观察哈希，以及源文件标识、策略和先前结果是否保持一致；比较器核对五种子、候选完整性及指标汇总。新命令不读取训练 CSV 或测试 CSV，不训练模型，不调用语言模型。

比较包含：

- 固定模型参照：始终使用初始 LightGBM，只承担基线五次训练成本。
- 固定顺序搜索：按冻结候选目录的顺序尝试候选。
- 宿主 Agent：回放实际提交的三个动作顺序。
- 随机搜索：固定基线在第一位，对剩余三个候选枚举全部六种排列，按均匀分布汇总。

每步都只使用该顺序中已出现的候选结果，并复用执行器相同的晋级检查。预算以完成评估的候选数表示，1、2、3、4 个候选分别对应 5、10、15、20 次训练尝试。随机策略在同一预算上的最小值、最大值和均值来自六种排列，不是置信区间。Oracle 是回放后的完整目录参考，仅供判断改善机会，不能用于宿主决策。

## 计量边界

累计评估时间是原候选执行耗时的重排累加，不代表重新计时，更不包含 LLM 推理、工具调度和人工成本。固定模型参照不会为了凑满搜索预算而重复训练。状态文件和比较代码哈希保存在输出中；输入结果是本地可信实验记录，哈希链不是对恶意篡改者的密码学认证。

由于候选目录很小且全部结果已经获得，本实验只能评估这个目录上的顺序差异。六种排列共享完全相同的候选测量，不是六个独立数据集或六次独立 Agent 实验。当前宿主轨迹只有一次，也不能估计语言模型策略的方差。

## 2026-09-08 实际结果

最终核验输出为 `reports/search_comparison/2026-09-08-verified/comparison.json`、`budget_summary.csv` 与 `trajectories.csv`。此次新增模型训练数和 LLM 决策轨迹数均为零，复用了之前的 20 次训练测量。核验包括初始状态仅含基线、停止后没有追加动作，且对同一次读取的快照字节计算哈希。

| 1 | 5 | 0.7491 | 0.7491 | 0.7491 / [0.7491, 0.7491] |
| 2 | 10 | 0.7491 | 0.7491 | 0.7491 / [0.7491, 0.7491] |

| 4 | 20 | 0.7491 | 0.7491 | 0.7491 / [0.7491, 0.7491] |

所有最终配置都是 all_48 + LightGBM，整体 Macro-F1 为 0.8224，过渡区 Macro-F1 为 0.5632。完整目录分析得到可晋级候选数为 0，所有预算点的改善目标达成率为 0。实际宿主的候选顺序恰好与固定目录顺序一致，因此两条轨迹相同不是两个独立策略重复实验的证据。

仅采用固定基线需要 5 次训练、已有评估耗时约 11.05 秒；执行完整搜索需要 20 次训练、回放累计约 37.36 秒。在当前结果中，额外搜索没有带来分数收益，而宿主推理成本尚未计入。不能据此宣称 Agent 更节省资源，也不能推断 Agent 在有改善机会的更大目录上无效。

校验测试另外构造了存在改进候选和过渡区退化候选的小型数据，确认前缀顺序能够产生差异、不能读取未来候选来提前晋级、退化候选会被拦截。合成测试证明比较实现的行为，不是实测模型性能证据。

## 可检验性的下一步

如果目录中不存在可晋级候选，所有顺序都可能保持基线，此时实验没有区分搜索方法优劣的机会。不能靠增大随机排列次数改善这一点。需要先依据训练误差假设扩展有限动作，例如训练采样策略或类别权重；在新一轮执行前冻结动作与预算，并将候选数设为大于实际试验预算，再比较固定流程、随机顺序与多次宿主轨迹。新增候选必须先有独立的数值模型研究依据，不能为了证明 Agent 有效而利用测试集挑选目录。
