# 读取失败证据后的显式停止

本轮把已有的基线、类别权重和中点采样结果接回 v3 状态机，以检验在预算未耗尽时，语言模型宿主能否根据类别退化证据提交明确停止动作。

## 实际完成的流程

1. 校验策略影响实验与中点会话的数据哈希、基线逐种子结果一致。
2. 从冻结输出读取三个候选、各五种子的完整诊断，重新运行晋级逻辑，未直接继承旧 accepted 字段。
3. 宿主读取基线保留、类别权重15个违反项、中点采样7个违反项以及剩余1个候选预算的观察结果。
4. 宿主提交带观察哈希的 stop 动作，状态从 active 转为 stopped，保留原始 paper_smote 配置和1个未使用预算。

产物为 `reports/agent_stop/completed/`：四份递增状态快照和 provenance.json。最后一份快照内保存停止理由，指出未验证候选仍有不确定性，停止不能解释成目录全部无效。

## 复现入口

```bash
.venv/bin/python replay_agent_evidence.py --output-dir reports/agent_stop/new-observation
```

这会回放三组历史验证结果并输出观察。宿主随后构造 `{"action":"stop","reason":"具体理由","observation_sha256":"最新观察哈希"}`，运行：

```bash
.venv/bin/python replay_agent_evidence.py --output-dir reports/agent_stop/new-completed --stop-action stop.json
```

此入口只接受 stop，拒绝经回放接口发起新训练。原有 run_mwd_agent.py 仍承担实际模型实验，两种状态目录不应混用。停止后的会话不能继续动作；输出目录不能覆盖已有结果。

## 证据与限制

新增模型拟合为0。这里引用了15次历史拟合的结果，回放中 elapsed_seconds 是缓存访问时间，不是模型训练耗时；保留1个预算不能报告为实测节省5次训练。三组证据生成于不同代码修订，来源路径、文件哈希与历史代码指纹保留在 provenance.json 中。

只有最后一个停止动作由本轮宿主基于观察提交，前三个候选的顺序是回放程序固定的，不是新 LLM 搜索轨迹。宿主事先知道这些结果，因此不支持搜索效率、停止最优性或盲测优势的主张。逐类别屏障是开发后的研究约束，不是现场安全保证。

现在闭环具备了读取类别证据、拦截退化候选、保留当前配置、未耗尽预算时明确停止的完整路径。本组采样实验到此收束；下一项核心研究应预先冻结独立宿主评估任务，比较相同可见历史与相同预算下的后续决策，不继续围绕这些已知结果调整阈值。
