# 自有现场数据与标签契约（采集准备版）

本契约服务于[总体路线](project-roadmap.md)的 B 线和 P3–P5。当前是采集及验收要求，不代表团队已拥有这些字段。现场负责人需为每一项填写“已有/可采/缺失”、来源、频率、单位和负责人。

## 1. 样本与关联关系

采用 `project_id → borehole_id → depth_segment_id` 和 `project_id → grouting_stage_id` 两组标识，通过关联表连接深度段与注浆段。一个注浆段可覆盖多个深度段，多个孔也可能共享施工或效果记录；禁止假设严格一一对应并直接复制成独立训练样本。

关联表至少含孔编号、深度段编号、注浆段编号、重叠深度、坐标参考、关联方法和关联可信度。工程、钻孔及批次标识用于分组和追溯；是否作为模型输入需另行审查部署可用性与捷径风险。

## 2. 字段清单

| 数据表 | 最小字段或信息 | 主要用途 |
|---|---|---|
| 工程与设备 | 工程/区域 ID，场景、设计版本、钻机/钻头、孔径、设备量程与能力 | 域差异、条件匹配和规则适用性 |
| 钻孔 | ID、位置、方位、倾角、孔口基准、施工起止时间、钻孔用途 | 空间对齐、分组和施工顺序 |
| 原始 MWD | 孔 ID、时间戳、深度、实际可用的钻速/推进/回转/冲击/冲洗参数、单位、质量码 | 工况识别与地质表征；保留原始值 |
| 工况与设备事件 | 接杆、停钻、冲洗、空转、报警、换钻头、参数设定变化及时间 | 区分操作变化和地质变化 |
| 地质与水文标签 | 起止深度、岩性、完整性/破碎程度、出水/漏液/压水证据、来源、可信度、标注人 | 独立监督与异常核验 |
| 注浆段与方案 | 段 ID、位置/深度范围、孔关联、材料、配比、设计边界、初始方案及版本 | 连接地质认知与决策 |
| 注浆过程 | 时间戳、压力及测点、瞬时流量、累计量、当前配比、泵状态 | 过程状态与响应建模 |
| 建议与实际动作 | 建议时刻、输入快照、建议、依据、审批、实际动作及执行时刻、未采纳原因 | 回放、时延、行为差异与采纳分析 |
| 治理效果 | 检查孔/压水试验/残余涌水等指标、单位、时刻、空间范围、测量条件 | 效果评价；不以注浆量替代治理效果 |
| 规则与案例来源 | 文档/案例 ID、版本、适用条件、生效时间、可用时间、审核状态 | 决策依据与防止未来信息进入回放 |

缺失传感器不作为一律否决项；记录可用模态，并限定相应任务。若没有原始时序，就不验收工况识别和时序清洗；若没有独立水文证据，就不验收富水识别；若没有动作日志，就不验收闭环策略效果。

## 3. 时间、深度与量纲

- 同时保存测量/发生时间 `event_time` 与系统可获得时间 `available_at`，并注明时区、时钟来源、采样率和同步误差。回放按后者控制信息可见性。
- 深度必须说明沿孔深度、垂深或隧道里程，记录零点、单位、回退与重钻处理。时间到深度的转换保留版本、原始索引和误差。
- 压力区分泵端、孔口或其他测点；流量和累计量注明浆液体积或材料质量及单位。累计量的清零、换段、回流等事件单独记录。
- 原始值、清洗值和插补标记分开存储，不覆盖原始记录。统计特征保留窗口、算法版本及所需传感器列表。
- 不同数据源的归一化含义必须核对。不能只因名称相近就把现场压力等原始量直接填入公开数据的 `Norm`/`RMS` 特征列。

## 4. 标签规则

完整性/破碎程度和水文证据分别标注，再按审核后的工程规则组合为状态。保留 `unknown`、证据不足、标签冲突和不适用；不得强制所有样本落入完整/破碎/富水破碎三类。

标签记录观测深度、覆盖范围、观测方法、采集时间、可获得时间、标注人、复核人与可信等级。优先采用独立编录、取芯、孔内电视、揭露或水文试验。MWD 异常可以触发复核，不能同时作为富水标签的唯一生成依据和模型输入来证明有效性。

标签允许晚于钻进获得，用于事后监督，但必须与在线输入分离。专家对部分样本独立复标，记录一致性与争议处理。来自注浆反馈的推断作为旁证，不能自动覆盖原始地质标签。

## 5. 试采集与版本验收

先选择可追溯的正常、异常和缺失案例完成端到端对齐演练，不设置未经现场依据的通用样本数要求。扩大采集前确认：

1. 孔/段主键唯一，关联关系可追踪，重叠和多对多关系不产生重复计数。
2. 时间、深度、单位与压力测点明确；同步和空间误差经抽样核验并记录。
3. 缺失、停钻、清零、掉线等有标记；地质突变不会因统一滤波被静默消除。
4. 标签来源可核验，未知与弱标签单列；独立钻孔数、区域数及异常事件数有统计。
5. 回放样例无法读到当时未知的结果、动作、案例或后验标签。
6. 注浆段与效果的关联范围明确；无法区分的共享效果不复制成多个独立结果。
7. 数据发布权限、存储位置、脱敏方案和访问责任明确。

数据版本 manifest 保存文件哈希、schema 版本、采集范围、处理配置、拆分单元、异常清单和审核记录。用于外部/最终评价的数据在协议冻结后留出，专家规则、阈值和提示词开发不查看其结果。

## 6. 缺口如何影响路线

| 数据缺口 | 可继续的工作 | 等待补齐的结论 |
|---|---|---|
| 只有汇总特征 | 表格分类、校准、拒识与接口验证 | 原始时序处理、工况识别 |
| 有时序，无可靠地质标签 | 数据质量和工况审计、标注准备 | 地质识别有效性 |
| 有地质标签，无水文证据 | 岩性或破碎程度任务 | 富水破碎带识别 |
| 有注浆曲线，无实际动作时间 | 状态识别及受限的描述性分析 | 动作响应与闭环策略效果 |
| 有建议与动作，无效果对照 | 可用性、采纳、约束及过程评价 | 耗浆、工期和治理效果改善 |

现场原始数据默认留在受控存储，公开仓库提交字段定义、处理代码、合成接口样例或经授权的脱敏汇总。模拟数据只用于接口演练，不能纳入现场有效性结果。
